# 故障排查

先定位故障发生在哪一层：浏览器、Java、Python、数据库、Redis、模型供应商或外部渠道。不要同时修改多个配置碰运气。

## 登录出现 CORS 错误

现象：浏览器提示缺少 `Access-Control-Allow-Origin`。

检查 Java 是否真正运行在 8080：

```powershell
Test-NetConnection localhost -Port 8080
Invoke-WebRequest -Method Options http://localhost:8080/api/auth/login \
  -Headers @{ Origin='http://localhost:5173'; 'Access-Control-Request-Method'='POST' }
```

`SecurityConfig` 已允许 OPTIONS 和开发来源。若仍失败，通常是 8080 上运行了其他进程或 Java 启动失败。

## Java 启动失败

先查看最早出现的 `Caused by`。常见原因：

- PostgreSQL 未启动或密码不一致。
- 8080 端口被占用。
- Flyway 迁移曾失败并留下失败记录。
- JDK 版本过低。

```powershell
docker compose ps
Get-NetTCPConnection -LocalPort 8080 -ErrorAction SilentlyContinue
java -version
mvn -q -DskipTests compile
```

不要直接删除 Flyway 历史。先修复迁移 SQL，再根据环境决定 repair 或重建开发数据库。

## Agent 没有回复

依次检查：

1. Python `/health` 是否正常。
2. Java 到 Python 的 gRPC 地址是否正确。
3. `LLM_API_KEY`、`LLM_BASE_URL` 和模型 ID 是否有效。
4. Python 日志是否有 401、429 或超时。
5. 浏览器 SSE 是否收到 `error` 事件。

直接请求供应商可以区分“供应商问题”和“AgentHub 链路问题”。

如果日志出现“访问套接字被权限禁止”、`Permission denied` 或 `Network is unreachable`，但使用同一 Key 在普通终端直连供应商返回 200，问题在 Runtime 进程的网络沙箱、防火墙或出口策略，不是凭证。应在允许访问供应商 443 端口的运行环境启动 Java 和 Python，再分别验证供应商 `/models`、最小对话和 AgentHub 完整链路。诊断过程中只输出 HTTP 状态和供应商错误码，不打印 Key。

DeepSeek 模型目录以供应商 `/v1/models` 的实时结果为准；当前稳定 ID 为 `deepseek-v4-flash` 和 `deepseek-v4-pro`。数据库 V14 会迁移旧的 `deepseek-chat`、`deepseek-reasoner` 配置，历史 Trace 和用量记录保持不变。

## 文档上传成功但索引失败

检查 Java 文档状态和 Python 日志：

```bash
curl http://localhost:8080/api/knowledge/docs/12 \
  -H "Authorization: Bearer $TOKEN"
curl http://localhost:8000/rag/stats
```

常见原因：扫描 PDF 无文本、文件加密、文件超过 25 MB、Python 无法访问 Java 的 8080 地址。

容器内的 `localhost` 指向容器自身，应使用服务名，例如 `http://java-console:8080`。

## DOCX、PDF 内容为空

DOCX 应确认文件没有损坏。PDF 若是图片扫描件，需要 OCR；Tika 不会凭空识别图片文字。可以先用 `pdftotext` 或办公软件验证是否存在文本层。

## 渠道测试失败

- 400：通常未填写 Webhook。
- 401/403：外部平台凭据或签名错误。
- 404：Webhook 地址失效。
- 429：平台限流。
- 502：Java 无法完成外部投递。

生产环境还要检查出口代理、DNS、证书和 SSRF 白名单。

## 用量页一直为零

只有完整 Agent 对话完成后才会写入 `token_usage`。仅打开页面、编辑 Agent 或运行护栏测试不会产生 Token 用量。

```sql
SELECT model, input_tokens, output_tokens, cost, created_at
FROM token_usage
ORDER BY created_at DESC
LIMIT 20;
```

## 前端构建失败

```powershell
cd web-ui
npm install
npx vue-tsc -b --pretty false
npm run build
```

先修复 TypeScript 错误，再处理 Vite 打包问题。不要删除类型检查来绕过真实错误。

## 收集问题信息

提交问题时附上：复现步骤、期望和实际结果、浏览器控制台、Java/Python 相关日志、服务版本和操作系统。密钥、JWT、手机号、邮箱和文档内容必须先脱敏。
