# 工作台使用指南

工作台是 AgentHub 的管理面。它负责配置、审批、审计、知识资产和运行观察；模型推理由 Python 执行面完成。

## 工作台首页

首页只展示后端已有数据：服务健康、Agent 数量、待审批任务和最近活动。数字为零表示当前没有记录，不会自动填充演示数据。

推荐日常检查顺序：

1. 确认 Java、Python、PostgreSQL、Redis 状态正常。
2. 处理待审批事项。
3. 查看失败执行和审计事件。
4. 查看预算与模型用量。

## Agent 管理

Agent 定义包含名称、系统提示词、模型、温度、最大 Token 和发布状态。

创建 Agent 时，系统提示词应包含职责、输入边界、工具使用条件和输出格式。例如：

```text
你是合同审阅助手。
只分析用户上传的合同内容，不补充无法从原文确认的事实。
涉及付款、删除或外部通知的动作必须先请求审批。
输出包括：风险级别、原文位置、问题说明、修改建议。
```

草稿 Agent 可编辑，发布后才适合绑定生产渠道。修改模型前先在“对话实验室”验证输出质量。

## 对话实验室

对话实验室通过 Java 的 SSE 接口调用 Python 执行面。页面右侧展示模型、工具和审批事件，便于判断回答来自模型、知识库还是工具。

真实调用链路：

```text
Browser -> POST /api/agents/{id}/chat -> Java gRPC client
        -> Python runtime -> model/tool/RAG -> SSE -> Browser
```

对话完成后 Java 会写入审计日志和 `token_usage`，用量分析页据此汇总。

## 知识库

知识库支持上传 PDF、DOCX、XLSX、PPTX、TXT、Markdown、CSV、JSON、HTML、XML 和 YAML。上传后 Java 使用 Apache Tika 提取文本，Python 负责切片和向量索引，切片同时回写 PostgreSQL。

删除文档会同时删除数据库记录和 Python 内存索引。若 Python 重启，会从 Java 接口恢复已持久化切片。

## 流程编排

流程由入口、Agent、审批、工具和输出节点组成。编辑后点击“保存草稿”，配置写入 `workspace_resource`；点击“运行流程”，后端创建 `workspace_execution` 记录。

当前流程遇到人工审批节点时会进入 `waiting_for_approval`，不会越过卡点伪装完成。外部模型或工具凭据未配置时，应先完成相应节点配置。

## 安全护栏

启用状态、规则说明和发布状态都保存在 PostgreSQL。试验台请求服务端执行，当前内置手机号、邮箱脱敏和提示词攻击检测。

自定义规则会先保存为草稿。需要更复杂的分类模型时，可在 Java 控制器或 Python 运行时扩展规则执行器。

## 渠道接入

网页和 API 是本地渠道；企业微信、钉钉、飞书和自定义渠道需要 Webhook。配置保存后再发送测试消息，系统会返回真实 HTTP 投递结果。

渠道启用不代表外部凭据有效。生产前必须完成一次测试投递，并在外部平台确认收到消息。

## 审批与审计

高风险工具由 Python 创建审批任务，审批人通过 Java 管理面批准或拒绝。每次状态变化都会进入审计日志。

审批时重点核对：调用者、目标资源、输入参数、风险等级、业务影响和幂等键。不要只根据 Agent 的自然语言说明批准操作。

## 用量分析

用量页读取 `token_usage` 的真实记录，展示本月输入/输出 Token、调用数、模型费用和近七日趋势。预算上限写入 `budget` 表，不保存在浏览器。

当没有模型调用时，页面会显示零和空表，这是正常状态。
