# 部署运维指南

生产部署应将 Web、Java、Python、PostgreSQL 和 Redis 作为独立服务管理。Java 与 Python 可以分别扩容，但必须共享统一配置和追踪标识。

## 推荐拓扑

```text
Browser -> HTTPS Gateway -> web-ui
                       -> java-console -> PostgreSQL
                                      -> Redis
                                      -> gRPC -> python-engine -> LLM API
```

不要直接把 Python gRPC 和数据库端口暴露到公网。

## Docker 启动

开发环境：

```bash
docker compose up -d postgres redis
```

生产镜像应固定版本，不使用 `latest`。数据库迁移由一个 Java 实例先执行，确认成功后再扩容其他实例。

## 环境变量

关键配置分组：

```dotenv
# Database
DB_HOST=postgres
DB_PORT=5432
DB_NAME=agenthub
DB_USER=agenthub
DB_PASSWORD=replace-me
REDIS_URL=redis://:replace-me@redis:6379/0

# Runtime
PYTHON_GRPC_HOST=python-engine
PYTHON_GRPC_PORT=9091
PYTHON_RUNTIME_URL=http://python-engine:8000
AGENTHUB_INTERNAL_TOKEN=replace-with-a-random-secret-of-at-least-32-characters

# Model
DEEPSEEK_API_KEY=sk-replace-me
# OPENAI_API_KEY=sk-replace-me

# Web
VITE_API_URL=/api
VITE_RUNTIME_URL=/runtime-api
```

Vite 环境变量在构建时写入前端，绝对不能放密钥。

## 健康检查

```bash
curl -f http://java-console:8080/api/health
curl -f http://python-engine:8000/health
redis-cli -h redis ping
pg_isready -h postgres -U agenthub
```

健康检查应区分“进程存活”和“依赖就绪”。模型供应商故障不一定要让管理面退出，但应在工作台明确显示不可用。

## 日志与追踪

每个请求生成 trace ID，并在以下位置传递：HTTP Header、Java 日志、gRPC metadata、Python 日志、工具调用和审计记录。

日志至少包含时间、级别、服务、trace ID、用户 ID、Agent ID 和事件类型。禁止记录 JWT、API Key、完整银行卡和未脱敏文档内容。

## 数据备份

每日备份 PostgreSQL，升级前额外创建快照：

```bash
pg_dump -Fc -h postgres -U agenthub agent_hub > agent_hub.dump
```

恢复演练比备份成功提示更重要。至少每季度在隔离环境验证一次完整恢复。

Redis 当前用于运行时协调，不应作为唯一持久化存储。知识切片和工作区配置必须可从 PostgreSQL 恢复。

## 发布流程

1. 在 CI 运行 Java 测试、Python 测试和前端构建。
2. 备份数据库并检查 Flyway 迁移。
3. 先部署 Java 单实例并执行迁移。
4. 部署 Python，验证 gRPC 和模型连接。
5. 部署 Web 静态资源。
6. 执行登录、对话、审批、知识检索和渠道测试。
7. 观察错误率、延迟和模型成本。

## 回滚

应用镜像可以回滚，数据库迁移不应依赖自动向下迁移。破坏性 Schema 变更使用“扩展 -> 双写 -> 切换 -> 清理”流程，确保旧版本在过渡期仍可运行。
