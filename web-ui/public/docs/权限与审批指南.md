# 权限与审批指南

权限决定“谁可以发起”，审批决定“高风险动作何时可以继续”。两者必须同时存在，不能用审批代替基础权限校验。

## 权限模型

AgentHub 使用用户、角色、权限点的 RBAC 结构。推荐权限命名：

```text
agent:read
agent:write
agent:publish
tool:execute
approval:review
audit:read
workspace:admin
```

后端方法可以通过注解限制权限：

```java
@PreAuthorize("hasAuthority('agent:publish')")
@PostMapping("/{id}/publish")
public ApiResponse<Void> publish(@PathVariable Long id) {
    agentService.publish(id);
    return ApiResponse.ok();
}
```

前端隐藏按钮只能改善体验，不是安全边界。后端必须独立校验。

## 审批生命周期

```text
pending -> approved -> executing -> completed
        -> rejected
        -> expired
```

审批记录至少包含：申请人、工具名、参数快照、风险等级、业务摘要、创建时间、过期时间、审批人和决定理由。

## Python 创建审批

高风险工具执行前，由 Python 调用 Java 内部接口：

```python
payload = {
    "sessionId": context["session_id"],
    "agentId": context["agent_id"],
    "toolName": "refund.execute",
    "arguments": arguments,
    "riskLevel": "high",
    "summary": "退款 6800 元至原支付账户",
}
await java_client.post("/api/approvals/create", json=payload)
```

创建成功后，执行引擎必须暂停当前动作，不得先执行再补审批。

## 审批页面操作

审批人应核对参数和业务对象。批准时写入审批人、时间和意见；拒绝时要求填写原因，并将原因返回原会话。

审批按钮需要防重复提交。后端更新应使用状态条件：

```sql
UPDATE approval_task
SET status = 'approved', reviewer_id = ?, reviewed_at = NOW()
WHERE id = ? AND status = 'pending';
```

受影响行数为 0 表示任务已处理或过期。

## 审计要求

以下事件必须记录：

- 用户登录与失败登录。
- Agent 创建、修改、发布、删除。
- 工具调用和参数摘要。
- 审批创建、批准、拒绝、过期。
- 权限和角色变更。
- 知识文档上传、索引和删除。

敏感参数应脱敏后进入审计日志，但要保留可关联的业务 ID。

## 生产建议

- 高金额操作使用双人审批。
- 申请人不能审批自己的任务。
- 审批链接短时有效并绑定用户身份。
- 权限变更立即失效，不依赖旧 JWT 长期缓存。
- 定期导出审计记录到不可篡改存储。
