# 知识库指南

知识库把企业文件转换成可检索的文本切片，供 Agent 在回答时引用。AgentHub 将原始文档元数据和切片持久化到 PostgreSQL，Python 维护运行时索引。

## 支持格式

当前支持：PDF、DOCX、XLSX、PPTX、TXT、Markdown、CSV、JSON、HTML、XML、YAML。单文件最大 25 MB。

扫描版 PDF 没有文本层时，Apache Tika 无法直接提取内容，需要先进行 OCR。加密文档应先解密再上传。

## 上传处理链路

```text
Browser multipart upload
  -> Java /api/knowledge/upload
  -> Apache Tika 提取文本
  -> knowledge_document 保存原文与状态
  -> Python /rag/index?doc_id={id}
  -> 文本切片并建立索引
  -> Java /api/knowledge/docs/{id}/chunks 持久化切片
```

页面只有在 Python 返回成功后才显示实际切片数量。

## 上传示例

```bash
curl -X POST http://localhost:8080/api/knowledge/upload \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@./handbook.docx"
```

响应中的 `data.id` 是文档 ID。触发索引：

```bash
curl -X POST "http://localhost:8000/rag/index?doc_id=12"
```

## 添加纯文本

短规则或 FAQ 可以直接添加，不必先生成文件：

```json
POST /api/knowledge/text
{
  "title": "退款规则",
  "content": "订单支付后 7 天内可申请退款……"
}
```

## 切片建议

合理切片应保留语义完整性：

- 制度、手册：按标题和段落切分，建议 500 至 1000 中文字符。
- FAQ：一个问答作为一个切片。
- 表格：保留表头并为每行补充字段名。
- 合同：按条款编号切分，不要跨条款拼接。
- 代码：按函数或类切分，保留文件路径。

重叠区用于保留上下文，但过大重叠会增加索引和模型成本。

## 检索结果验证

索引完成后，不要只看“已索引”状态。应使用 5 至 10 个真实问题检查：

1. 正确切片是否进入前几名。
2. 返回内容是否包含文档名和位置。
3. 相似但无关的条款是否被错误召回。
4. 删除文档后是否不再被检索。

运行时统计：

```bash
curl http://localhost:8000/rag/stats
```

## 更新与删除

重新索引同一文档时，Python 会先删除旧切片，避免重复召回。删除操作同时调用：

```text
DELETE http://localhost:8000/rag/docs/{doc_id}
DELETE http://localhost:8080/api/knowledge/docs/{doc_id}
```

Java 或 Python 单边失败时，页面会显示错误。修复服务后重新删除或重新索引即可恢复一致。

## 数据安全

- 上传前确认文档的数据级别和使用范围。
- 包含个人信息的知识库应启用输出脱敏护栏。
- 生产环境使用对象存储保存原文件，数据库只存元数据和提取文本。
- 删除操作需要审计；敏感文档建议使用软删除与保留策略。
