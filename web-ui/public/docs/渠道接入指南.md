# 渠道接入指南

渠道层负责把 Agent 能力分发到网页、开放 API 和企业协作平台。Agent 配置不因渠道变化而复制，所有渠道共享审计和用量记录。

## 网页与开放 API

网页渠道通过 SSE 对话接口获取增量回复：

```http
POST /api/agents/{agentId}/chat
Authorization: Bearer {jwt}
Content-Type: application/json

{"message":"查询订单 A1024","sessionId":"session-001","userId":"1"}
```

响应事件可能包括 `text`、`tool_call`、`approval_required`、`error` 和 `done`。

## 企业微信

在企业微信管理后台创建应用或群机器人，获取 Webhook、Token 和 EncodingAESKey。工作台中选择“企业微信”，填写凭据、绑定 Agent、保存并发送测试消息。

回调接收端需要：

1. 校验签名和时间戳。
2. 解密消息。
3. 将外部用户映射为组织用户。
4. 生成稳定 session ID。
5. 调用 Agent 执行并按平台格式回复。

## 钉钉

钉钉测试消息使用文本机器人格式：

```json
{
  "msgtype": "text",
  "text": {"content": "AgentHub 渠道连通性测试"}
}
```

启用加签时，服务端还需按钉钉规则生成时间戳和签名。不要在浏览器计算签名或暴露 Secret。

## 飞书

飞书 Webhook 测试格式：

```json
{
  "msg_type": "text",
  "content": {"text": "AgentHub 渠道连通性测试"}
}
```

复杂回复可升级为消息卡片，但卡片模板应在渠道适配器中维护，Agent 只返回结构化业务结果。

## 自定义 Webhook

工作台可创建自定义渠道。服务端以通用结构发送：

```json
{
  "text": "AgentHub 渠道连通性测试"
}
```

生产适配器建议支持自定义 Header、签名算法、响应码白名单和重试策略。

## 配置与测试

渠道配置保存在 PostgreSQL：

```json
{
  "enabled": true,
  "agentId": 3,
  "webhookUrl": "https://example.com/webhook",
  "timeoutSeconds": 30,
  "retryCount": 2,
  "membersOnly": true,
  "saveConversation": true
}
```

测试接口会真实请求 Webhook：

```bash
curl -X POST http://localhost:8080/api/workspace/channel/8/test \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"message":"连接测试"}'
```

HTTP 成功只说明 Webhook 接收请求；仍需在目标平台确认消息展示正确。

## 安全与稳定性

- Webhook 只允许 HTTPS，生产环境限制内网地址，防止 SSRF。
- 凭据应加密存储，当前开发配置不应直接用于生产。
- 重试使用指数退避，并携带幂等 ID。
- 保存外部消息 ID，避免平台重复回调导致重复执行。
- 对每个渠道设置独立限流和熔断。
