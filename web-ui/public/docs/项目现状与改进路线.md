# AgentMesh 项目现状与改进路线

> 最后更新：2026-08-22
> 判断原则：只有能够指向代码、自动化测试或真实联调记录的事项才标记为完成；生产基础设施和供应商控制台配置单独列出。

## 当前结论

AgentMesh 已完成本机 Alpha / MVP+ 的主要工程闭环。Vue 控制台、Spring Boot 管理面、Python Runtime、PostgreSQL/pgvector、Redis、gRPC、工作流 worker、知识索引任务、渠道 worker、审批审计和模型目录校验均有实现。真实 DeepSeek 工作流和真实 Python 工具工作流已经从数据库队列执行到最终结果。

当前不应宣称“企业生产就绪”。剩余门槛集中在公网入口与 TLS、企业微信主体域名、外部 IdP、托管数据服务、双地域集群、恢复演练和容量压测，而不是继续增加演示页面。

## 已实现但仍需生产验收

- 飞书、企业微信和钉钉 HTTP 回调具备签名、解密、租户路由和异步 worker，但只有钉钉 Stream 已在当前凭证环境连接验证。
- Kubernetes、Kustomize、双地域 overlay、PDB/HPA、恢复与迁移 API 已交付，尚未在真实双地域集群完成故障切换。
- DashScope 多模态适配器与真实凭证已配置，模型区域权限、额度、计费和数据条款需在每次生产上线前复验。
- MCP、开发者网关、供应链扫描和制品签名已实现，仍需接入组织级 CI 门禁和密钥轮换流程。

## 剩余外部配置

1. 为 `agentmesh.asia` 准备公网服务器、负载均衡或托管入口，并配置 TLS；得到真实目标后再创建根域和 `console/api/callbacks` DNS 记录。
2. 使用企业主体可验证的 HTTPS 域名完成企业微信回调验证，填写 `WECHAT_CALLBACK_URL`。
3. 接入真实 OIDC 或 SAML IdP，完成 SSO 登录、登出、用户同步和证书轮换验收。
4. 采购或部署生产 PostgreSQL、Redis 和 Kubernetes；完成备份恢复、双实例、双地域切换、容量与故障注入测试。
5. 按需配置 Anthropic、Moonshot、Zhipu、Mistral。未使用的供应商不需要购买或填 Key。

## 后续路线

### 生产基础设施

- 建立公网入口、WAF/TLS、密钥托管、日志与告警。
- 将 PostgreSQL、Redis、对象存储和向量数据纳入备份、恢复和容量模型。
- 在真实多实例环境验证 worker 租约、重复投递、长任务取消和滚动升级。

### 质量与产品化

- 扩展 Playwright 到创建 Agent、发布、审批、知识同步、渠道重放和人工复核七条任务流。
- 建立回答级引用正确性、召回质量、成本和延迟评测集。
- 完成全站设计 token、统一状态组件、键盘可用性、对比度和全量中英文覆盖。

### 发布门槛

- 公开写入口在缺少或伪造凭证时全部拒绝。
- 至少一个真实模型和一个真实企业渠道形成可重复契约测试。
- 多实例不重复执行、不丢会话、不跨租户读写。
- 完成生产备份恢复、密钥轮换、故障切换和容量压测记录。
- 文档中的每个“完成”均能回溯到测试、脚本或外部验收证据。
