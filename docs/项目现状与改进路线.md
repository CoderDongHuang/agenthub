# AI Agent Hub 项目现状、问题审计与演进路线

> 审计日期：2026-08-10  
> 审计范围：`java-console`、`python-engine`、`web-ui`、数据库迁移、部署配置及项目文档  
> 当前判断：项目已具备可构建、可演示的 MVP+ 闭环，但尚未达到企业生产环境的安全性、可靠性和可运维性要求。

## 1. 项目定位与背景

AI Agent Hub 是面向企业的 Agent 管理与治理平台，目标不是单一聊天机器人，而是把 Agent 的创建、模型接入、工具调用、知识库、审批、审计、渠道发布、成本统计和运行治理放在统一控制面中。

当前采用三层架构：

- Vue 3 控制台与产品官网负责配置、管理和交互。
- Spring Boot 管理面负责用户、权限、Agent 元数据、审批、审计、资源配置和对外 API。
- FastAPI/Python 运行时负责 LLM 调用、会话执行、工具执行、RAG 和流式输出。
- Java 与 Python 通过 gRPC 交互，PostgreSQL/pgvector 保存业务数据，Redis 已进入部署拓扑但尚未承担核心会话状态。

## 3. 必须优先处理的问题

### 3.1 P0：接口授权边界不完整（已于 2026-08-11 修复）

落地结果：Java API 改为默认拒绝，登录/注册、健康检查和 API Key 网关按路径放行；内部 Agent、审批、工具与知识同步统一使用内部服务身份；Python RAG 与运行时管理端点也要求内部凭证；CORS 改为环境配置的精确 Origin。

`SecurityConfig` 将审批创建、工具注册、知识库文档接口和内部接口设为公开路径。部分接口依赖控制器自行校验，部分接口没有等价的内部认证机制。`/api/knowledge/docs/**` 会同时放开查询、分块写入和删除路径。

风险：未授权读取或删除知识、伪造审批、注册恶意工具、跨边界调用内部 API。

建议：

1. 默认拒绝，明确列出真正公开的健康检查、登录和 API Key 网关。
2. Java-Python 内部调用统一使用短期服务 JWT 或 mTLS，不使用公开路径加静态字符串。
3. 为每个业务接口增加方法级权限，例如 `@PreAuthorize`，并补充 401/403 集成测试。
4. 将知识库内部同步接口迁移到 `/api/internal/knowledge/**`，用户 CRUD 保持 JWT 鉴权。

### 3.2 P0：多租户隔离尚未贯穿新模块（已于 2026-08-11 修复）

落地结果：JWT 认证主体从数据库恢复可信 `userId/tenantId`，不再信任浏览器传入的租户头；Agent、审批、工作台、用户、工具、审计、计费、API Key、知识库、平台统计和 RAG 均按租户过滤，Java-Python 调用透传可信租户。

`WorkspaceResourceController` 多处固定使用 `tenant_id = 0`、`created_by = 1`，Agent 创建和“我的审批”也使用固定用户 `1L`。部分按 ID 查询、更新和删除没有租户条件。

风险：不同租户之间可能读取、修改或删除对方资源，审计主体也会失真。

建议：所有 Repository/JdbcTemplate 查询必须显式带 `tenant_id`；用户 ID 从认证上下文取得；为跨租户访问编写负向集成测试；禁止业务代码出现默认租户和默认用户常量。

### 3.3 P0：内部令牌存在可预测默认值（已于 2026-08-11 修复）

落地结果：删除所有可预测默认值，Java 启动和 Python 内部调用要求 `AGENTHUB_INTERNAL_TOKEN` 至少 32 字符，校验使用常量时间比较；示例配置仅保留明确占位符。

`application.yml` 和 `InternalAgentController` 都为 `AGENTHUB_INTERNAL_TOKEN` 提供了 `agenthub-local-runtime` 默认值。

风险：生产环境漏配时会自动启用公开已知凭证。

建议：仅在 `local` profile 提供开发值，其他环境启动时强制校验；令牌使用密钥管理系统注入并支持轮换；日志中不得记录令牌。

### 3.4 P0：渠道测试存在 SSRF 面（已于 2026-08-11 修复）

落地结果：Webhook 仅允许无用户信息的 HTTPS 443 地址；发送前解析全部 DNS 地址并拒绝环回、私网、链路本地、组播、共享地址空间和其他非公网地址，新增安全回归测试。

渠道测试会从数据库配置读取任意 `webhookUrl` 并由后端发起请求，当前未见协议、域名、内网 IP、重定向和 DNS 重绑定限制。

风险：攻击者可探测或访问云元数据、本机和内网服务。

建议：仅允许 HTTPS；使用域名白名单；解析并阻断环回、私网、链路本地和保留地址；禁用或逐跳校验重定向；设置严格连接/读取超时和响应大小上限。

### 3.5 P1：工作流执行仍是模拟器（已于 2026-08-12 修复）

工作流运行目前遍历节点并直接把普通节点标记为完成，遇到审批节点即停止，没有实际调度 Agent、工具、分支、重试、补偿或恢复。

建议：引入持久化状态机和任务队列；定义节点输入输出契约；支持幂等键、超时、重试、取消、人工恢复和事件日志；将前端“运行成功”文案与真实执行状态严格对应。

### 3.6 P1：会话与 RAG 索引仅驻留 Python 内存（已于 2026-08-12 修复）

`SessionManager` 使用进程字典保存会话，`Retriever` 使用列表保存向量。进程重启、横向扩容或多 Worker 时状态不一致。虽然文档分块会回写 PostgreSQL，但向量检索仍不是 pgvector 的生产实现。

建议：会话迁移到 Redis，并设置 TTL、容量和租户前缀；Embedding 与向量写入 pgvector；检索使用带租户过滤的 SQL/向量索引；增加重建索引任务和版本控制。

### 3.7 P1：模型清单与真实供应商能力可能不一致（已于 2026-08-12 修复）

模型注册表包含未来版本、推测型号或可能不存在的 API ID，例如 DeepSeek V4、Claude Sonnet 5 等。前端展示与运行时配置需要同源，否则用户可能创建无法运行的 Agent。

建议：建立由后端返回的模型能力注册表；逐个使用供应商官方文档核验模型 ID；记录上下文长度、流式/工具调用支持、价格和停用日期；加入启动时连通性检查与降级策略。

### 3.8 P1：认证令牌保存在 localStorage（已于 2026-08-12 修复）

JWT 由前端存入 `localStorage`，一旦发生 XSS 即可被脚本读取。当前 Markdown 渲染、第三方依赖和未来自定义工具界面都会扩大 XSS 面。

建议：Web 控制台优先使用 `HttpOnly + Secure + SameSite` Cookie；配套 CSRF 防护；至少启用严格 CSP、依赖审计、Markdown HTML 禁用/净化和短期 Access Token。

### 3.9 P1：旧路由缺少兼容跳转（已于 2026-08-12 修复）

当前仅定义 `/console/dashboard` 等新路径，没有 `/dashboard`、`/agents` 等旧路径重定向。历史书签或缓存会触发 Vue Router `No match found`。

建议：增加一组显式 legacy redirects，并在一个版本周期后移除；为主要导航路径添加路由测试。

## 4. 功能正确性与工程问题

### 4.1 错误处理泄露内部细节（已于 2026-08-13 修复）

多个控制器直接把 `exception.getMessage()` 返回客户端，Python 端也有大量宽泛 `except Exception`。这会暴露内部 URL、SQL、供应商信息，同时难以区分可重试与不可重试错误。

建议：统一错误码、Trace ID 和对外安全文案；内部堆栈只进入结构化日志；对超时、限流、鉴权、参数错误和供应商错误分别建模。

### 4.2 CORS 配置过宽（已于 2026-08-13 修复）

Java 端允许任意 Origin、Method 和 Header。即使 JWT 当前通过 Authorization Header 发送，生产部署仍应限制可信站点，未来切换 Cookie 后更是必要。

建议：按环境变量维护精确 Origin 列表，仅允许实际使用的方法和请求头。

### 4.3 演示模式可能掩盖配置错误（已于 2026-08-13 修复）

没有模型 Key 时，Python 运行时自动返回演示回复。这有利于本地体验，但生产漏配时可能表现为“请求成功”，造成错误判断。

建议：演示模式必须由显式环境变量启用；生产环境缺少模型凭证时启动失败或返回明确的配置错误。

### 4.4 企微、钉钉、飞书尚未真正闭环（已于 2026-08-13 修复）

适配器中仍有 TODO，企微 XML 验签/解密、钉钉签名、飞书事件校验、重放保护和回调幂等尚未完成。

建议：每个渠道独立实现认证、消息标准化、发送重试、幂等和死信；用供应商沙箱做契约测试。

### 4.5 API 类型安全不足（已于 2026-08-13 修复）

前端大量使用 `as any` 和自由结构 `Map<String, Object>`；工作台资源依赖 JSONB 动态结构，编译期无法发现字段漂移。

建议：用 OpenAPI 生成 TypeScript Client；Java 使用请求/响应 DTO；工作流、渠道和护栏分别定义版本化 Schema，并在入库前校验。

### 4.6 文档存在双份维护（已于 2026-08-13 修复）

根目录 `docs` 与 `web-ui/public/docs` 存在重复内容，后续修改容易不一致。

建议：保留单一文档源，构建时复制或由 Vite 导入；在 CI 中校验链接和 Markdown 构建。

## 5. 性能与稳定性优化（已于 2026-08-14 完成）

### 5.1 前端加载性能

落地结果：Element Plus 改为 19 个实际组件和 `v-loading` 按需注册；入口 JS 从约 1,035.78 kB 降至约 60.60 kB，全局 Element Plus CSS 从约 376.65 kB 降至约 155.05 kB。Vue、Element Plus、图标、Markdown 与图形库已拆分为独立 chunk，路由页面继续按需加载。

Lightfall 已支持离屏、后台标签页暂停，低性能设备限制为 30 FPS、关闭抗锯齿并降低 DPR，`prefers-reduced-motion` 下限制为 12 FPS；组件卸载时释放监听器、动画帧和 WebGL 资源。原 353 kB 的 Logo 与 favicon 已分别换成紧凑资源。生产构建生成 Brotli 预压缩文件，Nginx 配置启用静态资源一年不可变缓存、HTML 禁止缓存和 `brotli_static`。

本地开发统一使用 Vite 同源代理：Java `/api`、Python `/runtime-api`，避免跨域和写死端口。CSRF Token 自动注入所有写请求；Token 失效时仅对写请求刷新并重试一次，覆盖后端重启和长时间打开页面的场景。

### 5.2 Java 数据访问

落地结果：工作区资源查询和执行历史已抽到 `WorkspaceResourceQueryService`；工具、资源和执行历史从内存分页改为数据库 `COUNT + LIMIT/OFFSET`，全局默认每页 20、最大 100。V11 为工作区执行、审计、Token 用量、审批和工具的高频租户查询增加复合索引。

JPA 已关闭 Open Session in View，移除显式 PostgreSQL 方言并关闭未使用的 Redis Repository 扫描。控制器继续负责 HTTP 契约，分页、只读查询和 JSON 规范化集中到服务层；月度统计保留数据库聚合，后续只有在数据规模达到瓶颈时才引入预聚合表。

### 5.3 Python 执行性能

落地结果：模型缓存改为有界 LRU/TTL，默认最多 16 个实例、TTL 3600 秒；模型调用按租户和模型默认并发 4，工具默认总并发 8，参数均可通过环境变量调整。工具同步失败不再静默成功，采用有限重试并计入指标。

gRPC `StopSession`、客户端断开和协程取消已形成真实取消传播，`CancelledError` 不再被普通异常吞掉。同步 gRPC 健康检查通过 `asyncio.to_thread` 移出事件循环；Uvicorn 仅在显式设置 `UVICORN_RELOAD=true` 时启用热重载。运行时能力接口暴露请求数、错误数、取消数、平均耗时、平均首 Token 延迟和重试次数，不暴露凭据。

### 5.4 测试与 CI 性能

PDF 测试改用 PDFBox 内嵌 Liberation Sans，不再扫描整机字体。Node 固定为 22.19.0，Python 固定为 3.11.9，Python 直接依赖精确锁定，并解决 `litellm` 与 `httpx` 的版本冲突。

GitHub Actions 已建立 Web 构建、Java 测试和 Python 测试三个独立任务。本轮实测：前端生产构建通过并生成 10 个 Brotli 文件；Java 15/15、Python 15/15 全部通过；三端健康检查、Java-Python 双向 gRPC、DeepSeek 真实 SSE 对话、护栏检测、工作流保存/运行、本地渠道测试和 18 个主要 API 读取链路均通过。

### 5.5 稳定性回归修复

- Java 聊天执行器从无限线程池改为默认并发 16、队列 64 的有界线程池，容量耗尽时明确失败，应用关闭时主动清理。
- Agent 执行前按当前租户校验 Agent，Token 用量记录实际模型；运行时 `ERROR` 记为失败审计且不写成功用量，页面不再生成空白回复。
- Spring Security 6 掩码 CSRF Token 已覆盖注册、普通 API 和 SSE；403 不再误跳登录，过期 Token 支持一次安全刷新重试。
- V12 将旧演示模型 ID 迁移到当前稳定目录；前端新建 Agent 默认选择已配置供应商。
- Logo、配置文件和 Markdown 均按 UTF-8 校验，未发现替换字符或 mojibake；PowerShell/重定向日志的终端编码不作为源文件编码。

## 6. 建议扩展的产品能力

### 6.1 近期高价值能力

本节八项能力已于 2026-08-16 完成，统一收敛到控制台“发布与运行”页面，并提供对应的 Java API、数据库迁移和运行时接入。

1. **Agent 版本管理**：支持从当前配置创建不可变草稿快照、版本列表、字段级配置 Diff、10% 灰度、全量发布和一键回滚。灰度期间按会话标识稳定分桶，同一会话不会在版本之间随机漂移；常规 Agent 发布也会生成版本并执行评测门禁。
2. **离线评测与发布门禁**：支持 Prompt、Tool、RAG 三类评测集，提供 `contains`、`exact`、`regex`、`json_contains` 和 `citation` 断言、用例权重、评分阈值及版本门禁状态。未通过门禁的版本不能发布。
3. **完整会话 Trace**：Agent 对话已记录模型、工具、审批、输入输出、Token、费用和延迟，页面提供 Trace 列表、Span 时间线、详情与 24 小时汇总；失败调用也会保留可定位的错误 Span。
4. **模型路由**：按成本、延迟、质量、地域和健康状态综合评分，跳过熔断端点；Java 的路由结果通过 gRPC 变量覆盖 Python Runtime 的模型、供应商、Base URL 和版本配置。
5. **知识库增强**：支持来源游标增量同步、SHA-256 内容去重、来源版本、ACL 继承、Chunk 引用溯源与检索效果评测，重复内容不会反复生成索引。
6. **工作流增强**：支持把现有工作流保存为模板、从模板实例化、通过 `subflow` 节点复用子流程，以及使用定时触发器和带一次性密钥的 Webhook 触发器启动执行。浏览器跨域调用 Webhook 时允许 `X-Workflow-Secret` 请求头。
7. **模型稳定性**：支持真实 HTTPS 健康探测、健康结果上报、连续三次失败自动熔断、恢复窗口和成功后关闭熔断；路由器会自动选择仍满足约束的健康端点。
8. **配置诊断中心**：自动检查 PostgreSQL、Redis、Python Runtime、模型 Key、JWT、内部服务 Token、CORS、钉钉、飞书、企业微信及模型路由健康度，并给出回调域名、事件订阅和平台权限提示。诊断接口只返回状态和修复建议，不返回任何 Secret 值。

### 6.2 企业治理能力

本节七项能力已于 2026-08-17 完成第一阶段落地：

1. **企业身份与细粒度访问**：支持 OIDC/SAML 配置结构和安全地址校验，敏感凭据只允许引用租户密钥库；支持一次性 SCIM Token（数据库只保存 SHA-256）、SCIM 2.0 User/Group 载荷同步、部门和角色映射；ABAC 按资源、动作和主体/环境属性按优先级决策，未命中时默认拒绝。现有 RBAC 继续负责菜单/API 角色门禁。真实外部 SSO 登录仍需用户提供可访问的 IdP，当前不虚报第三方登录成功。
2. **租户级 KMS**：敏感字段使用 AES-256-GCM、每条记录随机 12 字节 Nonce、租户 ID 和密钥版本作为 AAD；数据密钥由本地主密钥按租户和版本派生。列表接口不返回密文或明文，查看操作写入审计；轮换会逐条解密、使用新版本重加密并退役旧版本。
3. **数据治理与合规**：支持审计、Token 用量和 Trace 的保留/匿名化策略、Legal Hold、执行前预演、租户数据导出、删除证明和本地控制证据报告。报告明确标注范围为本地租户控制，不冒充外部机构认证。
4. **多层安全护栏**：统一扫描 Prompt Injection、中英文越狱表达、邮箱/手机号/证件号/银行卡、可执行文件签名和高风险扩展名，以及工具参数中的命令/SQL 注入、路径穿越和私网 SSRF；返回 allow、redact 或 block 及分层证据。
5. **动态审批策略**：按工具、金额上下限、数据级别、时间段和调用方组合条件匹配 auto approve、single、dual 或 reject 决策，并返回命中策略、理由和 SLA。
6. **值班与 SLA**：支持主值班/备班、时区和有效时段；扫描逾期审批后标记 SLA、记录升级时间并转派备班。审批中心现有响应式页面作为移动端审批入口。
7. **恢复、迁移与可验证删除**：支持不包含托管密钥材料的租户 JSON 导出、租户范围备份清单、SHA-256 完整性验证、只读恢复演练和目标租户迁移计划；密钥、身份源和访问策略的真实删除会生成可重复校验的删除证书。

### 6.3 平台生态能力

以下七项能力已于 2026-08-18 完成第一阶段落地，控制台统一入口为 `/console/ecosystem`：

1. **工具 SDK、签名包、沙箱和私有仓库**：提供可安装的 Python SDK，覆盖开发者网关、MCP Client 和工具包构建；私有制品在服务端使用 HMAC-SHA256 签名并校验内容摘要，列表不返回制品正文；执行前按超时、内存、CPU、网络域名和只读挂载评估沙箱策略，越权配置直接阻断。
2. **MCP Client/Server 互通**：Python Runtime 暴露 MCP Streamable HTTP JSON-RPC 端点，支持 `initialize`、`tools/list` 和 `tools/call`；Java 控制台可保存 HTTP/SSE/stdio 连接并对 HTTP 端点执行真实握手探测。stdio 只保存经过路径穿越校验的本地配置，不在控制台进程中任意拉起命令。
3. **Agent 开发者网关**：开发者密钥只展示一次，数据库使用 AES-256-GCM 保存；请求同时校验 API 版本、租户路由、时间窗、Nonce、防重放、签名和分钟配额。`agent.chat` 只允许调用同租户已发布 Agent，并通过现有 Java -> Python gRPC Runtime 返回真实回复；同时提供连通性、能力、应用和签名规范查询接口。
4. **多模态抽取流水线**：文档、图片和音频统一进入类型识别、内容摘要、结构化抽取和语义阶段；文本、JSON、CSV、PDF 和 Office 文档使用 Apache Tika 完成本地内容抽取。未配置 OCR、视觉或语音供应商时，图片/音频语义阶段明确返回 `needs_provider`，不把文件元数据伪装成模型理解结果。
5. **Kubernetes、弹性伸缩和容灾模板**：提供 Java、Python、Web 三端容器、Kustomize base、主/备地域 overlay、HPA、PDB、NetworkPolicy、拓扑分散和非 Root 运行配置；控制台支持按队列水位计算 Worker 期望副本以及只读容灾预演。双地域 PostgreSQL/Redis 一致性仍由外部托管数据服务负责，本机未虚报真实多地域集群部署。
6. **插件/MCP 供应链安全**：发布和重扫统一验证签名、摘要、来源协议、SemVer 兼容范围、依赖版本固定和高风险权限；输出可审计的风险分数、发现项与 `passed`、`warning`、`blocked` 结论，高风险包不能作为可信制品使用。
7. **本地优先开发套件**：`scripts/dev.ps1` 支持环境自检、一键启动和停止，首次运行生成本机随机服务密钥；`scripts/health-report.ps1` 输出服务、Docker 和仓库状态，自动脱敏并明确标记不包含 Secret；示例 Kubernetes Secret 仅保留占位符。

## 7. 推荐实施路线

### 阶段 A：安全基线（1-2 周）

- 收紧所有接口授权，内部调用改为服务身份。
- 消除固定 tenant/user，完成租户隔离测试。
- 修复 SSRF、默认令牌、CORS 和错误信息泄露。
- 核验模型 ID，关闭生产环境隐式演示模式。

验收：越权、跨租户、SSRF 和默认凭证安全测试全部通过；生产配置缺失时快速失败。

### 阶段 B：真实执行闭环（2-4 周）

- 会话迁移 Redis，向量检索迁移 pgvector。
- 工作流接入真实 Agent/工具执行和持久化状态机。
- 完成至少一个企业渠道的真实回调闭环。
- 建立模型、工具、RAG 和审批的 Trace。

验收：服务重启后任务可恢复；双实例运行状态一致；真实渠道端到端可重复验证。

### 阶段 C：质量与可运维性（2-3 周）

- 建立 GitHub Actions：lint、类型检查、单测、集成测试、镜像构建和依赖扫描。
- 引入 Testcontainers 完成 PostgreSQL/Redis/gRPC 集成测试。
- 增加 Playwright 登录、Agent 创建、对话、审批和知识库 E2E。
- 接入结构化日志、指标、Tracing、告警和健康探针。

验收：关键链路具备自动化回归；部署可观测；故障可定位；发布可回滚。

### 阶段 D：产品化与规模化（持续）

- 版本、评测、灰度、成本路由和配额。
- SSO/SCIM、合规、密钥托管和数据治理。
- SDK、MCP、工具市场和模板市场。
- 前端包体、后端查询、运行时并发和缓存专项优化。
